# Vyuha demo sprint

Planning and coordination for the demo build agreed on the call of 2026-08-27.
Two people, ten features, one demo.

This folder holds **the plan**, not the output. The generated sales artefacts
(`vyuha-demo-input.xlsx`, `vyuha-demo-dashboard.html`) live in the parent
`Project V/demo/` folder and are regenerated by `vyuha.sample.build()` —
different folder, different purpose, don't confuse the two.

Full plan with the status matrix and the calendar:
https://claude.ai/code/artifact/fb4f13cd-c7b5-4d35-9aff-4553b6f6d2ad

---

## 1. The rule that decides everything else

Ten features built independently gets you ten things that each demo for forty
seconds and none that survive a question. So: **one fictional business, one
timed story, each of the ten items a moment inside it.**

If it is not a beat in the script below, it does not get built before the demo.

**The business:** Shree Agro & Hardware, Belagavi. Two branches, ~60 SKUs across
agri-inputs and hardware, six regular customers, nine months of sales history,
and a stock register kept in Excel by the owner's son.

## 2. The script — one day, eleven beats

This is the definition of done. Tick a box when the beat runs end to end with
nobody touching a terminal.

- [ ] **08:00 — The morning brief arrives on WhatsApp.** Three items below
      reorder, cash locked in dead stock, overdue past 60 days. He has not
      opened a computer. — *item 04, 02*
- [ ] **— Nobody sent Vyuha anything.** Cut to the file it read: their real
      stock register, junk rows, merged title, "Grand Total" and all.
      Untouched. This is the sales moment. — *item 01*
- [ ] **08:04 — One tap: "Order these."** A purchase-order email to the
      supplier, quantities pre-filled from the reorder gap. — *item 04*
- [ ] **09:30 — A customer WhatsApps an order** in plain words. It lands in the
      Orders panel already parsed into lines against real SKUs, with a
      confidence mark on anything guessed. — *item 05*
- [ ] **09:32 — Tap "Quote".** Prices from the catalogue, margin visible to the
      operator only, PDF back on WhatsApp in the same thread. — *item 06*
- [ ] **11:00 — The owner asks a question in his own words.** "Who owes me most
      and since when?" Answered from his numbers, with the figure and where it
      came from. — *item 03*
- [ ] **15:00 — The money screen.** Cash in, cash out, due this week, margin by
      category. — *item 08*
- [ ] **19:00 — The evening report.** Today's sales, week to date vs last week,
      three suggestions. — *item 04*
- [ ] **+7d — The quote never converted.** A follow-up is drafted and waiting,
      referencing that quote. Approved in one tap. — *item 07*
- [ ] **— Switch branch.** Same screens, different numbers. The Hubballi
      manager sees his branch only; the owner sees both. — *item 10*
- [ ] **— "Make me a case study on this client."** A deck falls out, same
      numbers as every other screen. — *item 09*

## 3. Before either of us writes a feature (Vishak, days 0-2)

Not architecture work, not optional. The difference between building in
parallel and merging `app.py` every evening.

- [ ] **Break up `ui.py`** (1,727 lines) into a `ui/` package, one module per
      screen. `app.py` is another 1,003. Both lanes touch them daily.
- [ ] **Add `llm.py`** — one entry point for every Claude call, on-disk response
      cache, `VYUHA_LLM=offline` mode. Three AI features means three ways to
      hang mid-demo otherwise.
- [ ] **Kill the threshold globals.** `analyze.py` holds thresholds as module
      constants and `app._thresholds()` swaps them behind a lock. Scheduled
      morning runs make that a live race. Thread a `Thresholds` object through
      `analyse()`.
- [ ] **Seed the demo tenant** — `python -m vyuha_platform demo-seed`: wipe and
      rebuild Shree Agro with 2 branches, 60 SKUs, 9 months of sales, 3 planted
      dead SKUs, 2 about to stock out, 4 overdue invoices. Same numbers on both
      machines, resettable in one command. Never demo off live data.

Roshan, same two days: environment up, run `python -m vyuha demo --open` and
`python -m vyuha_platform --open`, read `books.py`, `catalog.py` and `report.py`
end to end, read `CLAUDE.md` end to end, then commit the `Quote` stub.

## 4. The split — by owned files, not by feature number

"You take 1-5, I take 6-10" puts us both in the same two files every day.
Each lane owns its modules outright. The other person opens a PR, never an edit.

### Lane A — Vishak — the spine and the brain

Owns: `vyuha/`, `llm.py`, `agent.py`, `automate.py`, `inbox.py`, `sources.py`,
`ui/agent.py`, `ui/inbox.py`

- **01 Intake adapters** — Tally / Busy / Marg export shapes and Google Sheets,
  as aliases in `schema.py` plus converters in `sources.py`.
- **03 Business agent** — tools over `Insights` and `Book`. Answers with the
  figure and its source; says "not in your data" rather than improvising.
- **04 Automations** — morning brief, PO draft, evening report, suggestions.
  Scheduler is a `/cron/{key}` route hit by Windows Task Scheduler. Do not add
  a job runner for a demo.
- **05 Inbound orders** — Twilio sandbox webhook, IMAP poller, LLM parse to
  order lines, orders panel. Hardest item in the ten; assume all of week two.

### Lane B — Roshan — the counter and the paperwork

Owns: `books.py`, `catalog.py`, `quotes.py`, `followup.py`, `money.py`,
`people.py`, `decks.py`, `exports.py`, `ui/inventory.py`, `ui/quotes.py`,
`ui/money.py`, `ui/people.py`

- **02 Inventory screen** — stock in/out, bulk reorder-level edit, movement
  history, low-stock board using `catalog.glyph()` pictures. The landing view.
- **06 Quotation** — build from catalogue or from an inbox order, margin
  operator-only, quote PDF, WhatsApp send.
- **07 Follow-up** — a due queue keyed on `quote.id` and `quote.status`.
  Roshan owns the queue; Vishak's scheduler pulls it.
- **08 Financial tracking** — purchases and expenses in, cash-flow statement,
  margin by category, dues this week.
- **09 Deck generator** — brief to outline to PPTX, through `llm.ask` and the
  existing `to_pptx`. Never call `anthropic` directly.
- **10 Branches & staff** — branch on the client, staff accounts under one
  business, per-branch numbers, comparison view. First on the cut list, so
  start it last.

### Shared, with rules

`app.py`, `store.py`, `theme.py`, `ui/shell.py`, `CLAUDE.md` belong to neither
lane. In `app.py`: routes only, appended inside your own marked block
(`# ---- vishak` / `# ---- roshan`). Business logic in `app.py` is a bug.

### Joint, week one, evenings

**Item 01's field research.** Three businesses each, same six questions: who
updates stock, how often, in what, what breaks, what they already automate,
what they would hand over first. Highest-leverage thing either of us does this
month — it decides which adapters are worth building, and it is the same
conversation that gets us clients.

## 6. Working rules

1. **One branch per item** — `vk/03-agent`, `rp/06-quotes`. PR to `main` the
   moment that item's beat runs, not when the feature feels finished.
2. **Rebase before you type**, every morning. Two people in thousand-line
   files: a day of drift is an hour of merge.
3. **Tests before every push** — `.venv/Scripts/python -m tests.test_platform`
   (57 tests) and `-m tests.test_pipeline` (13). pytest is not installed; use
   the module runner.
4. **Fifteen minutes at 9:30** — what beat landed, what's blocking, did any
   shared shape change. On a call, not chat.
5. **This file is the scope.** Adding a beat needs both of us.
6. **Cut whole items, never half.** If behind, the order is:
   **10 people → 09 decks → 08 money.** Seven items at 100% demos better than
   ten at 60%, and is a better thing to have built.

## 7. Known risks

- **Two AI features live on stage** (agent, order parser). Pre-warm the
  `llm.py` cache with every scripted question so the stage run is a cache hit.
- **Inbound WhatsApp needs a public URL.** Build the "paste a message" box in
  the orders panel *first* — it demos the same intelligence and cannot fail on
  the venue's wifi.
- **Ten items, ~30 person-days.** Three days per item including integration and
  rehearsal. The cut list above is agreed in advance for exactly this reason.

## 8. The architecture thread — a logbook, not a workstream

Build the replica first; think about architecture alongside. Thirty minutes at
end of day, appending to `requirements/02-decisions.md` (append-only, one entry
per decision) every time the demo forces a shortcut we know is wrong at scale:

JSON files as the store · process-global thresholds in `analyze.py` · one
`activity.jsonl` for every account · no queue behind the scheduler · slugs
globally unique because they name directories · no tenant database · every LLM
call synchronous and in the request path.

By demo day that file is the Phase 3 backlog, written from three weeks of
things that actually hurt rather than three weeks of speculation.

**One question worth settling before the demo, because it changes what we can
promise in the room:** is Vyuha one hosted platform every client logs into, or
an instance deployed per client? The `operator` / `tenant` split in `auth.py`
already anticipates both. Nobody has chosen. A prospect will ask.
